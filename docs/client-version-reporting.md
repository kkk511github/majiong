# 后台客户端版本统计

入口：管理后台 → 人员管理 → 更新情况。

- 默认目标版本是服务程序的 package 版本，与原生安装包版本可能不同；例如统计本次更新时可手动输入 0.9.2 查询。
- 按账号去重，显示全部账号、已达到目标版本、旧版本、版本未知；点击人数筛选对应名单，分页不会改变总统计。
- 统计跟随账号/昵称搜索、战队和账号状态筛选，包含管理员。
- 每行显示最近上报版本及上报时间，点击“刷新统计”获取最新结果。

## 数据口径

客户端已有 hello.clientVersion，因此仅版本统计不要求现有支持版本上报的客户端重新打包。新增平台统计需要新版客户端的 hello.clientPlatform（见下文）。登录凭据验证通过后才写入 client_version_reports；即使连接因最低版本被拦截，也保留该次上报。

只保存每个账号最新一次上报，不保存设备清单。断线与服务重启不清空记录；账号删除时清理该记录。新表不回填历史安装情况。未连接过、不带版本、非法版本都归“版本未知”；未知报告会覆盖该账号之前的版本，避免保留过时的已更新判断。

“已达目标”按数值版本比较（例如 0.7.100 小于 0.8.0），包含更高版本。版本来自客户端自报，可能为原生 App 或网页；它是最近使用版本，不是防篡改证明、在线人数或下载/安装人数。一个人多账号会分别计数；一个账号换设备后以最后一次报告为准。已安装但未打开连接的新版本无法确认。

仅后台管理员接口返回版本字段及汇总，不加入公共账号/牌桌数据。查询不改变强制更新开关或最低版本；只在认证 hello 时写一条记录，不在每次出牌发布时扫描全员。

## 验证

新增数据库写入/去重/未知/降级/删号清理测试，后台权限/数字版本比较/筛选/分页测试，真实 WebSocket 上报、强更拒绝记录、服务重启保留测试。后台桌面与手机浏览器验证统计卡片、筛选和版本列。

## 客户端平台人数（2026-10-01）

入口：人员管理 → 客户端平台。分别显示 iOS、安卓、网页版和平台未知，点击人数筛选会员列表；默认包含管理员，可选择“仅会员”或“仅管理员”。支持今天、近7天、近30天及全部时间。近7/30天按北京时间自然日包含今天，不是滚动168/720小时。

时间依据为最近一次通过身份验证的客户端 WebSocket 连接时间，不是实时在线人数，也不是设备安装量；持续连接跨日且未重连的用户不会自动获得新的连接时间。不同平台合计按账号去重，一个账号换设备以后只归入最后一次平台。手机浏览器仍归网页版，不通过 User-Agent 推测原生安装。只有最新快照，不支持回溯任意历史日期的平台分布。

平台人数跟随搜索、战队、账号状态、角色、版本及连接时间筛选，不随平台按钮改变各平台汇总。版本汇总跟随前述基础筛选，但不随版本状态或平台按钮改变。明细列表应用所有筛选。接口新增可选参数 `platform=ios|android|web|unknown`、`activity=today|7d|30d`、`role=member|admin`；空值表示全部，非法值返回400。权限仍仅限管理员。

客户端通过 `Capacitor.getPlatform()` 在 hello 中上报，服务端只接受 ios/android/web。非法或缺失平台显示未知，不拿诊断日志覆盖全体会员，也不沿用此前设备猜测。独立表 `client_platform_reports` 保留每个账号最新平台及连接时间，账号删除时自动清理。保持原版本表六列不变，兼容滚动部署中旧进程的 INSERT；读取时仅使用与最新版本记录时间匹配的平台，旧服务写入较新连接但未提供平台时显示未知。

上线需要部署服务端和网页后台；iOS、安卓平台上报需要重新打包并使用新版 App 连接，网页版需要发布新版网页。旧客户端可以继续正常使用，但平台会未知；还在旧牌桌服务上的连接需待新版服务处理后才能统计。本次不改规则、账单或强更策略。

验证覆盖：原表兼容、换设备去重、无效/缺失平台、较早记录不覆盖较新记录、删除清理、北京时间边界、权限、搜索/角色/版本交叉筛选、分页、真实 WebSocket 上报和重启保留。客户端 iOS/安卓/网页上报使用平台桥接 mock；后台浏览器交互使用测试数据，不代表生产人数，也不替代真机安装验收。
