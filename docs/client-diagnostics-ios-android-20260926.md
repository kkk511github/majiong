# iOS / 安卓诊断与主动上传

后续状态：服务端/后台已于2026-09-26部署，0.8.3 Build80安装包已交付，见 [部署记录](deployment-diagnostics-20260926.md) 与 [安装包记录](release-0.8.3-build80.md)。以下验证记录中的“未部署/未发布”指实现当时；未扩展为无限期或完整时间线日志，仍为24小时、最多32条。

## 已实现

- 新版两端：我的 → 帮助与反馈 → 上传日志。无需填写文字反馈；收到服务端确认才显示上传成功及编号。请求失败可重试，相同编号幂等；每会员主动上传限每分钟一次。
- 用户上传走独立登录态HTTP接口 `/api/diagnostics`，不依赖游戏WebSocket或牌桌资源成功初始化。用户不能指定日志归属账号。
- 后台人员管理 → 诊断日志：支持iOS和安卓主动采集、离线排队、查看报告，明确区分用户上传、后台采集、自动异常。后台会话按请求校验管理员权限。
- 新协议协商 `clientDiagnostics`，兼容旧安卓 `androidDiagnostics` 能力，不向不支持客户端发送新指令。
- iOS原生 `AppDiagnostics` 插件返回应用版本/构建、系统版本、机型、WKWebView信息；不采集设备唯一标识或用户自定义设备名称。
- 持久化来源字段有旧表迁移；原有后台请求恢复为admin来源，自动报告保持automatic来源。
- 本机最近24小时、最多32条事件；后台7天、全局2000条上限；后台离线请求24小时过期。账号切换/退出清空本地账号诊断上下文。隐私说明版本更新至2026-09-26.1。

## iOS兼容范围

共用牌桌运行包已包含不依赖Canvas roundRect的兼容路径，iOS原生工程已同步新资源。移除roundRect、Array.at、randomUUID和structuredClone的Chromium/WebKit构建回归通过。

当前工程、Capacitor 8及App/Filesystem/Share插件最低支持iOS15.0。用户追加要求“15.0以下”后，**未直接篡改最低安装版本，也未擅自降级原生依赖**。需确认最低目标是14、13或更旧，再选择兼容框架、插件并进行独立迁移回归。本次不能宣称支持15.0以下。

## 验证

- 全量99文件1375项单元测试通过。
- iOS/安卓主动上传：Chromium/WebKit共6个浏览器场景通过，使用隔离真实服务端与SQLite验证归属、持久化、管理员读取、限频；原生桥在这些浏览器场景中为模拟。
- 原生iOS插件已按deployment target15.0编译成功。
- 另在专用iOS26.5模拟器中，使用实际编译插件、独立测试App、隔离账号和本地真实服务端，完成后台请求 → 原生设备信息采集 → WebSocket回传 → 后台收到；以及用户HTTP主动上传 → 后台收到。两个来源均为received。结果位于 `output/native-diagnostic-probe/result.json`。
- iOS模拟器只能证明原生桥及链路可用，不等于iOS15或更低系统实测。本机没有对应旧运行时，Xcode下载15.5返回不可用。
- 正式账号与对局未用于测试。未部署服务器，未发布安装包；旧0.8.0 IPA不会自动获得修复与日志功能。

诊断不读取系统完整日志或其他App数据，不能唤醒已被系统关闭的App，也无法追溯旧客户端未记录/已清除的日志。原生进程被系统直接杀死时，不能保证生成JS异常堆栈。
