# 0.5.1 公平性与胡牌检查

2026-09-14，检查范围为当前代码及自动测试，不是第三方认证，也不是对“绝对公平”的承诺。

## 已落实的措施

- 联机牌墙只在服务端产生。Fisher–Yates 每一步直接使用 Node `crypto.randomInt(limit)`；单人练习使用 Web Crypto 拒绝采样，避免浮点换算造成的微小区间偏差。
- 发牌、摸牌、碰杠胡和计分由服务端检查。客户端不能提交指定牌墙、指定赢家或任意改分。房主、管理员、开桌授权和账号名称不参与发牌或胡牌计算。
- 其他人的手牌、摸到的牌、牌墙和响应选项不会发送给当前玩家。
- 本版修复了暗杠信息泄漏：其他玩家收到的暗杠只有类型与四张牌背，不再收到具体牌型；事件文本也不包含暗杠牌名。结算后才公开。
- 建桌大厅的正式牌桌只能坐四位真人，不能加入电脑。练习电脑的决策只依据自己的手牌与公开信息；修改其他人的暗手或牌墙次序不影响它的决策。
- 开桌授权单独保存，普通账号不能自授权。授权账号无权管理权限或查看管理员的全部牌桌战绩。每次权限变更记录管理员、目标、时间和新状态；被撤权后禁止新开桌、自动续桌，正在进行的对局继续。

## 胡牌验证

固定种子 1–1000，各打一局，四位简单电脑按当前引擎规则出牌：925 局有人胡牌，75 局流局，0 局卡住。座位胡牌次数分别为 235、231、236、236；一炮多响会使次数总和超过胡牌局数。这证明这批模拟没有“每局都无法胡牌”，不代表真人胜率，也不证明所有牌型规则都正确。

胡牌条件可满足时，在 568×320、844×390、932×430 横屏验证了“自摸”和点炮“胡”按钮可见、可点并能生成实际结算。暗杠隐藏后也验证了对手四张牌背能正常显示。

当前普通开门小胡有四个硬花的门槛，门清或符合大胡条件的牌不受这一门槛限制，因此只凑齐牌型不一定满足当前胡牌规则。现有规则仍是本项目的南京规则版本，并非已全面复刻微乐/荔枝。

## 仍存在的边界

服务器运营者掌握程序与数据库，尚无多方承诺/揭示的可验证洗牌、第三方独立审计，也不能通过程序杜绝线下串通。“风罚分”和“接庄比下胡”的具体算法尚未核准、未启用，不能宣称与荔枝完全一致。正常麻将允许流局，不能为了保证每把有人胡而暗改牌墙。
