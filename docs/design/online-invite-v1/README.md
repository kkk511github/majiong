## 现状与入口

现有约局列表的“邀请”调用复制房号，落座等待页也主要依靠房号分享。
本提案将已入座且未开局的牌友使用的邀请入口扩展为站内邀请：

1. 等待页保留现有座位、准备按钮与规则，在空座及“邀请”入口打开在线牌友列表。
2. 自己必须仍在本桌、桌子尚未开局且有空位，才能发送。
3. 原“复制房号”保留为弹层底部次要操作，不再是唯一邀请方式。
4. 不新增正式游戏桌右上角按钮，不恢复已删除的设置/大厅/记录入口。

## 邀请方

标题“邀请在线牌友”，下方持续显示目标桌号、已入座人数和剩余空位。
支持按昵称或公开会员 ID 搜索。名单显示头像、昵称和真实在线/占座状态：

| 牌友状态 | 显示与操作 |
| --- | --- |
| 在线、空闲、具备本桌入座资格 | 显示“邀请” |
| 已发出本桌邀请 | 显示“等待回应”与剩余时间，禁止重复发送 |
| 已在其他桌中 | 显示“对局中”或“已入座”，不可邀请 |
| 已在本桌 | 不再展示邀请操作 |
| 离线或不具备入桌资格 | 从可邀请列表移除，不泄露限制细节 |

点击后显示“邀请已发送”；对方接受时更新座位并提示“××已入座”，
拒绝时提示“××暂不加入”，过期时显示“邀请已过期”。
关闭名单只关闭弹层，不让已发送邀请悄悄失效。

## 受邀方

在线且空闲时，收到一个可操作的邀请弹层：

- 明确显示邀请人的头像、昵称、桌名与六位房号。
- 展示现有玩法摘要、把数、人数和占座预览；现有规则/计时/准备方式不改变。
- 两个同样容易点击的按钮：“拒绝”和“接受并入座”，接受使用金色主按钮。
- 推荐邀请有效期暂定60秒；超时只失效，绝不自动接受。
- 用户必须主动点击接受；仅通知、关闭弹层或倒计时结束都不能让其入桌。
- 接受后先显示“正在入座…”，服务端成功确认后才切换到这桌等待页。
- 入座后沿用本桌自动准备或手动准备设置，不额外替用户准备、不绕过开局同步。

## 边界与防打扰

1. **多人抢最后一个座位**：发邀请不预占座。接受时服务端原子检查并占座；
   后到的人显示“这桌已满”，留在原页面，不出现先跳转再踢回。
2. **桌子已开局、关闭，或邀请人已离桌**：使邀请失效并解释原因。
3. **受邀人已经进入另一桌**：不可自动离开当前桌；当前邀请不可接受。
4. **权限变化、掉线**：接受时重新检查身份、在线状态、入桌资格与空位；
   不信任发送时的旧名单，也不因邀请绕过禁赛/战队等现有校验。
5. **双击、重复报文与多端接受**：同一邀请只执行一次入座；
   任一端接受/拒绝后同步其他在线端状态。
6. **重复打扰**：同桌同用户只保留一条待回应邀请，并做发送频率限制。
   拒绝后建议设置短冷却，不马上反复弹窗。
7. **多条邀请**：同时只展开一张卡，其余提示有待处理邀请，不叠满屏幕。
8. **隐私与状态**：仅显示已有公开昵称、头像及必要的空闲/占座状态；
   不展示对方实时牌局牌面、手牌或私有信息。

## 后续实现验收范围

- 当前在线名单实时变化；离线/占座后按钮立即更新。
- 接受、拒绝、超时、断线恢复、满桌抢座、开局/解散后失效。
- 发送与接受的服务端权限验证、幂等入座及多人同步。
- 接受后进入正确桌子且不改原准备、托管、胡牌、算分逻辑。
- 横屏手机安全区内按钮均可触摸；长昵称省略、列表滚动、搜索无结果提示。
