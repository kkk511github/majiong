# 点选后拖牌与点击出牌兼容修复

用户操作：先点一下选中牌，再拖到桌面并松手即可出牌，不要求速度；原有选中后再次点击出牌继续保留。

## 已确认的原因

Cocos 3.8.8 的节点触摸分发会检查松手点是否仍在牌节点内。若正常 touchend 的最终坐标超出最后一次 touchmove 更新后的牌节点范围，引擎会发出 TOUCH_CANCEL。旧代码把该事件一律作为取消，因此出现牌已推到桌面却收回的现象。浏览器触屏事件已复现此路径。

另一个限制是旧手势要求纵向距离不小于横向距离，左右手牌斜拖到桌中央可能被拒绝。现在只检查选中状态、出牌权限、向上离开手牌区和最终桌内位置，不使用速度或横纵比例。

## 修复后的操作

- 本人出牌回合：第一次轻点选中，第二次轻点同牌直接出牌。
- 已选牌可慢慢拖到桌面，松手时提交一次出牌；拖动过程中不提交。
- 未选中直接拖动不出牌；不是本人出牌时可以预选，但不能打出。
- 向下拖、移动不足、拖回手牌、真正的系统触摸取消、失焦、切换牌局或失去出牌权限不提交。
- 通过浏览器真实 touchend / mouseup 标记区别正常松手与系统取消，按最终松手坐标判断。

## 验证

- 560项单元测试全部通过，TypeScript与Cocos构建通过。
- Chrome / WebKit的14项交互场景通过。初跑13项通过，WebKit构造Touch不兼容的测试辅助代码改为createTouch/createTouchList后，失败场景复跑通过。
- 鼠标回归覆盖568、844、1280横屏宽度。触屏回归覆盖先选后慢拖、斜拖、最后移动点与松手点不同、拖回手牌、系统取消、出牌回合变化。Chrome还使用CDP派发原生触屏输入；WebKit使用浏览器构造触摸事件，不等同于iPhone真机操作。
- 原失败路径在真实Cocos预览中复现后确认修复：引擎仍发送节点CANCEL，但一次正常松手仅提交一次discard且牌河增加一张。
