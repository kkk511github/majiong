# 战绩查询性能优化

范围：本地源码，未部署、未推送，未操作生产数据库。基准日期：2026-10-03。

## 改动

- 新增 `record_participants` 派生索引，按来源、账号、记录 ID 定位战绩；首次初始化事务内回填整桌和分局记录，后续启动不重新扫描参与者。
- 新增、修改 ID/参与者、删除、INSERT OR REPLACE、UPDATE OR REPLACE 均由触发器事务内维护索引。无效历史参与者 JSON 保留原文、不进入权限索引。
- 会员和个人查询先通过参与者索引定位候选记录，再按原有最新快照、日期、房号和阅读状态条件过滤。
- 房号仅允许数字，使用等价的 GLOB 前缀匹配以利用既有房号索引，支持前导零。
- 请求内批量读取会员编号、历史归队、管理员已读状态；头像按参与者复用。缓存不跨请求，元数据修正、改头像、切换账号仍即时生效。
- 标记已读保留当前持久化管理员角色、ID 格式和已结束桌存在检查，不再解析所有分局。
- 日历和列表总数筛选相同时复用 COUNT，日期范围不同时仍分别计算。
- 清理脚本支持新派生索引，并逐行校验保留记录的索引不变，保留备份、完整性和保护表校验。

没有修改麻将规则、积分账本、整桌结束日期归属、私密桌脱敏或阅读状态的账号隔离。

## 验证与限制

- TypeScript 检查通过。
- 全量 Vitest：136 文件、1884 项通过；随后补充 UPDATE OR REPLACE/回滚边界，索引和清理测试 2 文件、19 项通过。
- Chromium 战绩工作区与输入回归 14 项通过（568/844/1280 窄屏、桌面以及横屏安全区）。
- 额外运行旧 `external-records.e2e.ts`，2 项在已经移除的 `第 1 把明细` / `.round-player-points` 选择器失败；其真实数据库整桌分数断言已经通过。未修改页面或弱化断言来掩盖这一测试过时问题，外包回放端到端后半段未验证。
- 新增索引边界测试包括旧数据首次回填、重复启动、增删改、两种 REPLACE、事务回滚、查询计划、最新快照优先、历史转队、跨请求元数据更新、私密桌与无关会员拒绝、已读幂等和即时角色校验。

上线前应先备份数据库，在数据库副本上测量首次回填时间/空间和真实规模请求延迟，再安排服务升级。索引增加存储和写入维护开销；日期汇总仍解析完整筛选集合，总览 COUNT 仍与历史规模相关，本次未加入可能影响新鲜度的跨请求结果缓存。仍需线上网络、真实移动设备和更大历史规模验证。
