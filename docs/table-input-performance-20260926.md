# 出牌交互与牌桌流畅度优化

## 范围

本次优化客户端牌桌及 React/Cocos 通道，不调整计分、牌型、服务器操作确认或防重复出牌保护。之前尚未部署的杠上开花花数修复保持独立。后续已打入并交付 [0.8.4 / Build81](release-0.8.4-build81.md) 安装包；未上传发布更新，未切换生产服务。

## 修复

- 原 3D renderer 每次几何状态更新会销毁并重建所有模型；改为按牌槽和材质/形状签名复用。只有新增、移除、翻面、尺寸或高亮等实际改变才替换对应模型。
- 静止模型不再每帧重复投影和写入变换；HUD 的层级遍历按变化更新，异步特效仍处理正确显示层。
- 拖牌持续直接跟随输入，但只在第一次抬到前景时重排层级，取消/短拖明确触发回位。
- 自己手牌选中与回位过渡由 210ms 缩短到 120ms；摸牌插入、弃牌飞行、碰杠时序保留。
- 已选中牌再次点击时，牌桌端立即进入待确认状态，防止等待 React 往返时重复点击。
- 第一击的选牌确认如果落在第二击按住期间，只接受同牌、同桌/回合/行动上下文的本次确认，不把它当作外部换牌取消手势。其他选牌变化、换桌、断线、托管、禁用等仍取消。
- App 250ms 时钟刷新产生的相同状态不再重复跨 iframe 发送；牌桌 ready、页面恢复仍强制同步。非相同状态即时发送。

## 性能对照

同一本地桌面 Chrome，844×390 视口、密集弃牌 fixture、连续 12 次选牌，测量 `TableScene.draw()` 同步脚本耗时：

| 指标 | 修复前 | 修复后 |
| --- | ---: | ---: |
| 原有 138 个 3D 模型保留数 | 0 | 138 |
| 重绘耗时中位数 | 29.3ms | 1.5ms |
| 当次最大耗时 | 33.1ms | 3.0ms |

后续复测 Chrome 中位数仍为 1.5ms，WebKit 约 2ms。数据仅代表该本地脚本基准，不是 GPU 总帧时间或安卓/iOS 真机帧率承诺。

- `tests/table-motion-release.e2e.ts`：慢拖确认/拒绝/断线/超时、动画连续性、回放与同帧状态合并。
- `tests/production-table-3d.browser.ts`：材质/高亮、暗补杠接触、插牌、两把完整机器人流程及低版本 Canvas 兼容。
