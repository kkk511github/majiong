# Android 0.8.2 / Build 79：旧安卓等待页适配

针对用户提供的两人入座、两个空位的等待页截图。仅修改等待页布局/CSS与空位按钮短文案；牌桌、头像数据、邀请/准备行为、游戏规则及计分未变。iOS安装包未改，未部署或上传分发。

## 原因与修复

- 可用横屏高度256px时，旧网格中间轨道只有64px，而卡片实际140px，卡片上下溢出，覆盖标题和底部按钮；现代浏览器同样可以复现，旧机型的系统栏/放大字体会加剧。
- 轨道改用内容最小高度，标题、座位区、底部区域各占独立空间。极端字体或尺寸不足时在面板内滚动，不能重叠。
- 矮屏使用紧凑卡片，保留四席、完整昵称与“我”标记、邀请和准备按钮。触控按钮保持44px最小高度。
- 空位文案“邀请一位朋友”缩为“邀请好友”，原无障碍名称和操作回调不变。
- WebView 83不支持的 :is() 主题选择器增加显式等价选择器，恢复标题、状态、规则等文字对比度；按钮间距不用旧WebView不支持的flex gap。
- 房间号不拆字，昵称允许换行；不强行关闭系统字体放大。

## 验证

- 真实App等价状态的浏览器测量：1280×590、844×390、640×280、568×256，标题/房号、四卡片和底部不相交；底部可到达。
- 独立Android 11/API30模拟器，WebView 83.0.4103.120，640×280视口；用真实等待页DOM/CSS快照进行原生WebView渲染，TextZoom=100、150均通过几何和可滚动到按钮的检查。这是布局验证，不是连接生产房间的实战。
- 150%字体实测：标题底72px，座位区86.5–171.5px，底部186–260px；无覆盖。原生截图在 output/waiting-layout-compat/native-150.png。
- 1368项单元测试通过，4项Chromium/WebKit真实双端邀请回归通过。邀请浏览器测试原先把被邀请人建成管理员，与“管理员不可被邀请”规则冲突；改为普通会员测试夹具，未放宽生产权限。
- APK正式签名及16KB对齐通过；366项网页资源与native dist逐字节匹配。
