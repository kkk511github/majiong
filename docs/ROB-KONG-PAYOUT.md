# 当前B档抢杠赔三家

用户明确：甲只有七、九筒卡八筒，已开门、四张硬花，无其他软花或大胡。乙碰过八筒，摸到最后一张八筒补杠，甲抢杠胡。每份为成牌10＋压绝30＋硬花8＝48。

| 牌友 | 普通局变化 | 比下胡2倍变化 |
| --- | --- | --- |
| 甲，实际胡牌者 | ＋48 | ＋96 |
| 乙，被抢补杠者 | −144 | −288 |
| 丙，未胡、收到赔分 | ＋48 | ＋96 |
| 丁，未胡、收到赔分 | ＋48 | ＋96 |

抢成功不结算乙本次补杠的即时收费，也不为其补牌；原来的碰仍保留。抢杠没有额外再加一项固定牌型分。真正的胡牌者名单仍只有甲，丙、丁的赔分不使他们成为胡牌者，也不因此改变连庄判定。

花数和牌型资格按已确认的压绝规则：唯一卡张、胡到其他人公开碰过的同种第四张，自摸和点炮均可；压绝本身不免4硬花，门清或其他大胡仍可独立免花并叠加合法压绝。四花两面听虽无压绝，也可合法抢杠；按其实际胡牌单价赔给其余三家。

现有进园子余额上限保留：乙只有90分时，三家各收30；有整数余数时沿用付方座序分配。多人抢杠沿用现有逐胡者独立计账，每名实际胡者各触发一组对其余三人的赔付，付款人总应付仍为各胡者单价之和的3倍。先合并应付账单再按余额分摊。

## 记录与兼容

只改变当前 `nj-garden-b-v3` 的抢杠付款去向。旧休闲v1、进园子v2与敞开头v2保留旧付款规则。

新流水使用“抢杠赔三家”。旧流水“抢杠包三家”和旧金额保持，不按新规则回算。`Result.robbedKong` 记录真实抢杠事实，避免付款方余额过少、胡牌者未分到余数时丢失抢杠标签；仍以 `winners` 判定谁胡牌。回放与特效将付款来源写为“补杠被抢”。

每把收支、战绩、真实会员积分统计都记录三家实际收入；体验／机器人桌仍排除在日结、周结统计外。新明细展示单价、三家各自应得、总应付及实际转账，不把未胡受赔者标成赢家。

## 验证与发布

850项全量测试通过。覆盖四座轮转、八筒抢杠普通／比下胡、清一色叠加、余额不足与零余额禁抢、多人抢杠和过牌、旧规则兼容、真实账本与日报周报。Chrome／WebKit大小屏共4组真实牌桌视觉检查通过。

生产镜像内的离线核验和上线后的运行中镜像均验证：普通三家各48、比下胡各96、来源仅余90时三家各30。核验未向线上生成复现局或记分。

服务端和网页版发布为 `0.7.25-rob-three-20260919`，已有牌桌使用持久化状态恢复，三桌机器人保留自动续桌；本地预览服务也已重新加载。没有重新打包或替换APK／IPA，原生客户端本地文案需要后续包同步，真实分账由服务端立即生效。iOS仍必须先交用户签名，收到签回包后才允许上传。
