# 0.5.0 账号与牌桌结算

## 使用流程

- 首次打开先登录或注册。普通注册账号只能入座；管理员 `guanli@1` 可创建房间和批量开桌。
- 管理员账号由服务端初始化，注册界面不能抢注，也不能自行选择管理员。初始密码另行交付，首次登录必须更换。
- 账号支持修改密码、昵称、退出、跨设备登录。新登录会注销旧会话。未登录仍可单人练习。
- 当前只提供账号密码登录。未接微信 SDK，不显示无法使用的微信登录按钮；微信 AppID、审核及回调配置就绪后再接入。

## 分数与战绩

- 新桌每人本金 **100 分**，扣 **10 分桌费**，实际入桌 **90 分**。桌费只作为积分结算项目记录，不接入收款或支付。
- **桌上分**是当前余额；**分数**是桌上分减本金 100；**记分**是分数乘所选倍率（0.2、0.5 或 1，默认 0.5）。三个档位都固定扣 10 分桌费，折算分别为 2、5、10。
- 两家余额归零即结束整桌，付款不超过自己的桌上余额。结束时触发保米的胡牌者不足 100 分，由大赢家补至 100；不重复发放本金。
- 用户牌例：甲16、乙0、丙8、丁336；丙胡甲后为0、0、24、336，丁补76后为0、0、100、260。打50记分为 **甲−50、乙−50、丙0、丁+80**，合计−20对应四人的桌费。
- 旧桌沿用保存的原有基线和付款规则，不在更新中途扣桌费。续开的新桌使用100本金、10桌费、90入桌。旧版记录缺少本金字段时仍按原初始分显示。
- 管理员在「战绩 → 牌桌总战绩」查看**所有已结束牌桌的最终汇总**。5 桌各打 8 局，显示 5 条而非 40 条。
- 每条汇总包含房间号、完成把数、结束时间、四人排名、桌上分、输赢及记分。支持房号和日期筛选、分页、复制战绩。
- 管理员列表不会显示进行中的桌子。提前解散也保留最终战绩；同房间号续桌使用独立牌桌 ID，上一桌不覆盖。
- 个人仍可在「我的对局」查看自己的逐把明细。服务端逐把保存供个人查询，管理员入口只展示整桌汇总。
- 不展示未定义的“外包”假数据；已有承包收支仍包含在实际输赢中。

## 服务器与迁移

新增 accounts、account_audit、round_records、match_records 表，保留原 sessions、rooms、table_archives。更新前备份 SQLite；迁移会从旧归档补齐已保存的历史记录。

密码使用随机盐的 scrypt 派生；会话令牌随机生成，数据库仅存哈希。角色在每次联机操作和战绩请求时校验；新旧开桌接口都受保护。注册不能通过传 role 字段获得管理员。

持有效旧设备凭证注册时，可绑定该设备原有玩家 ID。普通账号之间不会共用本机联机战绩缓存。原先仅存在本机、且未保存到服务的匿名战绩不自动归到另一账号下。

首次管理员初始化：在服务器内将 JSON `{ "password": "由操作者生成的随机初始密码" }` 从标准输入交给 `tsx scripts/admin-account.ts`，数据库由 DATABASE_PATH 指定。脚本拒绝覆盖现有账号，不要将密码放在命令行或源码中。

## 验证

`npm test` 覆盖认证、越权、密码轮换、最终汇总、保米、两家干、桌费、三档倍率与旧负分记录迁移；`npm run test:e2e` 使用独立本地数据库、5178/8788 端口，不触碰正式账号。`npm run check:deployment -- https://safelink.chat/mahjong` 只检查健康、未授权访问拦截和原生客户端跨域配置。

现有南京特殊计分仍是 nj-casual-v1；本次实现 100 分本金、10 分桌费、90 分入桌和三档记分倍率；花砸 2、海底捞月、两家干与保米为可用选项。风罚分、接庄比尚待明确，详情见 [南京规则核验](./南京规则核验.md)。
