# 操作确认与重复请求边界

2026-09-16。以下结论针对出牌与碰杠胡操作，不把 requestId 描述为全站幂等键。

## 当前协议

- requestId 只关联一次操作的 ACK 或错误。服务器在保存并推送状态后确认。
- 普通出牌必须携带当前牌局 revision（版本）；成功出牌推进版本，旧请求再来会被拒绝并返回最新状态。
- 碰杠胡允许同一响应窗口内的旧版本，保证另一家先回复后，其他玩家仍可按原提示响应；每个座位只能回复一次，不能把“胡”改为“过”。
- 结算后旧胡牌请求无效，不能再次扣分或重复更新结果。
- 客户端确认超时后先恢复连接/状态，未知结果不会自动重发；同步完成前不能按旧手牌继续操作。

## 验证证据

`tests/server.test.ts` 使用真实 WebSocket：同 ID 与新 ID 重复出牌、同窗口重复响应/改写响应、多家胡牌并发、结算后重发，检查服务器牌局对象保持不变。`tests/client.test.ts` 覆盖 ACK 关联、状态先到、超时不重放及旧 socket 隔离。联合网络健康测试共52项通过，日志 `../../work/network-command-version-unit.log`。

这证明上述动作的版本与响应保护，不代表每个管理接口都有通用去重表，也不代表所有跨进程故障均已覆盖。

## 如果将来增加自动重发

必须先单独设计并验证：账号与桌/把的去重范围、请求内容摘要、同键不同内容的拒绝策略、保存动作与保存结果的原子性、保留期限、重启恢复以及重复请求的结果回放。不能只沿用 requestId 后直接开启客户端重试。当前本轮没有开启动作重发。

## 版本诊断

服务器在会话消息中报告 package.json 版本，设置页显示客户端/服务端版本并纳入手动复制的诊断。旧服务没有该字段时显示未提供，不沿用上一连接的版本；该版本号不是源码提交哈希。
