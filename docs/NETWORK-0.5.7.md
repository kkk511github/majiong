# 0.5.7 首页刷新和连接恢复

## 用户行为

每次从其他页面回到首页都会重新请求牌桌列表；已经在首页时，再点底部“牌桌”或顶部首页标识也会刷新。回到 App 前台、网络恢复时重新校时并刷新已订阅的大厅。正常刷新复用同一条 WebSocket；同一轮未完成的请求合并，避免重复点击产生多条连接。

刷新期间首页不把旧空位显示为可入座，大厅保留列表但禁用旧空位操作。收到新列表后恢复操作。

## 连接约束

- 列表查询不再被“等待准备/出牌确认”阻塞，查询返回也不能确认或解锁游戏命令。
- 列表 8 秒未返回、连接/鉴权握手 10 秒未完成，或支持校时的服务 10 秒未回复心跳，客户端会退役旧连接并重连。
- 重连退避从 1 秒起，最大 15 秒；网络恢复/返回前台可跳过正在等待的退避。进入后台暂停心跳超时判定，回前台发起新校时。
- 退役旧连接不等待 close 事件，避免网络切换时半开连接卡死。旧连接的消息、打开、报错回调都不能覆盖新连接或本地练习。
- 重连只取服务器状态与列表，不自动重放未确认的出牌、准备、开桌请求；账号在别处登录后，不自动抢回会话。

使用现有 hello/session、tables、ping/pong 协议，旧协议的能力检测保留。本版没有修改牌局规则、管理员授权或计分。

## 验证记录

先加入四项针对性用例，旧实现四项均失败（查询受操作锁阻塞、刷新请求未合并、列表超时无恢复、旧连接迟到回调未隔离）；修复后通过。最终逻辑/服务测试 139 项通过。

12 项界面专项通过，包含从四个页面返回首页、首页重复点击、同一连接复用、丢失列表回复后自动重连、刷新期间不允许点击旧空位、四真人入座准备、校时、结算续局。首次界面命令因未包含 npm 的 bin PATH 未能启动测试服务，改用 npm run 后正常运行，不计为产品用例失败。

最终全量 111 项界面回归通过；原生 iOS build 17 实际验证返回首页刷新并恢复服务器列表。SafeLink-212 0.5.7-a5ae6db0 healthy，账号战绩备份保留。包验证详见 network-0.5.7-check.json。此改动不代表所有移动网络环境、真实来电中断或安卓原生触摸都已实测。
