# 0.5.9 iOS 内置南京话播报修正

## 问题与修复

0.5.8 打包资源与浏览器声音检查通过，但独立 iOS QA App 实际点击“试听南京话”后，播放计数与目的节点音频电平均为 0。原生探针显示 fetch 返回 status 0、无 HTTP Content-Type，加载代码因此把本地音频误判为失败。

本地 Capacitor 8 的 WebViewAssetHandler.swift 对 wav 等媒体扩展使用 URLResponse，而非普通静态文件的 HTTPURLResponse(200)。原生结果与该分支一致。0.5.9 仅在当前页面与音频目标都是 capacitor://localhost 时允许 status 0，仍使用浏览器音频解码器检查数据；外部 HTTPS、其他本地主机和 404 等响应继续拒绝。没有放宽任何 API 请求或 TLS 验证。

## 证据

- 新回归先失败：iOS 本地 status 0 不创建声音源；另 10 项通过。
- 修复后音频专项 16 项通过，包括外部地址、其他主机、HTTP 错误拒绝。完整逻辑/服务 157 项通过。
- 独立 QA App 与正式模拟器 App 分开安装，正式账号和音乐/音效偏好未修改；探针未写入正式工程或分发包。
- 修复后原生读取 2,888,690 字节、解码 60.18 秒内置语音；试听播放 offset 29.47、duration 1.19（杠上开花），输出 RMS 0.0937、峰值 0.2375。
- 通过模拟器 Home 切到后台，page hidden / audio suspended；约 28 秒后返回自动恢复 running。播放计数仍为 2，没有回放旧声音，当前 RMS 为 0。
- 第三次试听过程中关闭播报开关，当前 RMS 回到 0；重新开启不增加播放计数、不补播。此处报告输出信号，不将其表述为用户对南京口音的听感确认。

0.5.8 已交付安装包保留为历史版本；请使用包含此修复的 0.5.9。真实 iPhone 来电中断、Android 原生音频听感和全部实际对局仍需后续验收；没有据此勾选完整体验目标。
