# Cocos 2.5D 牌桌重构

状态：0.7.0 / build 33。Cocos 牌桌和完整回放共用同一份渲染布局。

## 已核验的参考结构

2026-09-15，读取本机已缓存的小程序图片资源和 plist 元数据，没有进入牌局，也没有读取账号、聊天或其他玩家的实时数据。

- 牌体图集 462 帧，印刷牌面 194 帧；不是 462 种牌面。
- `hand / out / win` 区分手牌、弃牌与展示状态。
- `down / top / rl` 区分近端、远端和侧面；`cover / lie / stand` 区分朝下、平放、竖立。
- 同一种状态还随槽位切换牌体透视。例如侧手牌竖立 17 帧，近端弃牌平放 45 帧。不能旋转或拉伸一张正面图替代。
- 图集记录原尺寸、裁切矩形、偏移、是否旋转；这些数据必须参与锚点还原。
- 特效单独组织，不影响实体牌的占位。

原始缓存和解码查看文件仅存放在工作目录，不打入本项目、安装包或 Git 仓库。项目的牌体、纹理、模型和布局由本项目独立制作。

## 实现约定

1. 用 Blender 离线制作统一比例的圆角白色牌体、绿色背板和柔和光照，导出透明的多角度纹理。运行时不使用 3D 网格或实时灯光。
2. Cocos Creator 3.8.8 负责 Sprite 渲染、统一锚点、深度排序、触摸和动画。React 保留大厅、账号、管理和战绩；牌桌通过受约束的状态/指令桥接到已有游戏客户端。
3. 所有座位共享实体牌比例。四家分别使用真实渲染角度，不用 CSS 把正面牌压扁。
4. 手牌槽、花牌槽、碰杠槽、弃牌区独立。对家碰杠接手牌；两侧碰杠使用手牌与花槽之间的独立桌内区域，四组也不会向外挤出。第四张杠牌叠在中间。
5. 自己手牌贴近底边，右侧单独预留摸牌槽。操作按钮固定在手牌右上方，保持单行。
6. 数据只使用已有的公开 View；不从服务器请求其他玩家暗手牌。服务器继续负责判定合法操作。
7. 同一个 Cocos Web 构建用于 iOS 和 Android，保留既有原生网络、音频、录音及安全配置。

## 验收重点

四家牌体厚度和朝向；14 张手牌；4 组杠；多行花牌与弃牌；选牌听牌提示；最后弃牌指向器；横屏长宽比；双端点击命中；切后台恢复；完整回放和结算。

## 固定花槽与牌面投影

桌面使用独立制作的无槽底图；四个长花槽由共享的 `FLOWER_SLOTS` 坐标绘制，花牌也按同一组边界定位。自己与对家的花牌底部和卡槽边界对齐，两侧花牌使用独立的预渲染角度并贴紧排列。花槽与碰杠分别保留溢出空间。

侧家暗手牌使用立起的多角度牌背，单张不额外切变，整排沿花槽外沿布置。碰杠使用独立的 `meld-left/right` 视图，保持桌内占位；暗杠以背面展示。

四家首行弃牌轴线围成以 `(640,280)` 为中心、边长 296 的正方形：左右 `x=492/788`，上下 `y=132/428`。上下行水平、左右列垂直，相邻方向为 90 度，弃牌不再沿花槽倾斜。自己与对家最多两排向中间扩展，上下家最多三列向外扩展，转角预留空间。布局、贴图和 Cocos 构建在各平台共用。

### 两侧牌体与花牌厚度

侧面弃牌使用不切变的 `left/right` 预渲染牌图，排列旋转为零。花牌使用独立的 `flower-left/right` 厚牌体，按当前张数计算贴合间距，避免下一张盖住前一张的白色侧壁和绿色牌底。主槽可容纳 12 张，额外花牌进入上方独立预留槽。全部贴图保持统一裁切原点和固有比例。
