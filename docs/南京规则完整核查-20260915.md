# 南京麻将规则完整核查

> 本文保留2026-09-15最初针对 `nj-casual-v1` 的审查证据；下文“当前”“缺失”均指当时版本。后续已经实现的进园子、敞开头、外包账本等进展见[实现进度](./南京规则实现进度-20260915.md)和[当前规则](./RULES.md)，不要把此历史审查当作最新源码状态。

核查日期：2026-09-15。对象为本地 `outputs/nanjing-mahjong` 当前源码，规则标识 `nj-casual-v1`。

**结论：有遗漏。目前是已有说明的南京休闲规则，并不是完整的荔枝进园子、敞开头或已验证的微乐规则。** 主要问题是玩法档案未区分、特殊胡牌与跨局状态未接入、部分承包条件缺失，以及一个已复现的听牌提示错误。不能因现有测试通过就认定南京规则齐全。

本次完成规则审查、固定牌例复现和证据整理；没有改变实际计分、在线牌局、部署、原生包或牌桌布局。下述“当前通过”仅证明本项目现行规则中的对应行为，不表示已与其他平台一致。

## 一、核查依据

1. 当前引擎、计分、牌组、桌设置、计时、结算、回放、服务端和听牌提示实现，以及玩法页面文案。
2. 本项目已有 [可执行规则](./RULES.md)、[2026-09-13 核验记录](./南京规则核验.md) 和用户明确的本金、桌费、两家干、保米、暗杠隐私及托管要求。
3. 用户此前提供的荔枝安装包中抽取的南京玩法帮助：`work/lizhi-reference/rules1.txt`。这次重新读取了全文，明确区分其进园子、敞开头两节；它不是微乐服务端规则，也没有写全外包优先级等边界。
4. 外部对照：[唐人游南京规则](https://nanjingmj.uc55.com/Rule/Detail/201802_000241.html)、[来游戏南京规则](https://static.laiyouxi.com/games/44.html)、[哈灵进园子说明](https://www.haling.com/news/news_42.html)。这些来源各自的数值、坐庄、门清和特殊规则不同，不能拼成一套“标准南京规则”。

本次没有取得当前微乐小程序所选南京房型的完整帮助与建房选项。微乐官网的游戏介绍只能确认存在南京玩法，不能证明细节相同。下文把能确定的实现缺口和平台差异分开，未把未查到的条件猜成已实现。

## 二、优先处理的发现

### P1：计分没有区分进园子和敞开头

`shared/types.ts` 的 Rules 只有一个 `nj-casual-v1`；`normalizeRules` 没有玩法模式字段，`scoreHand` 使用同一组固定大胡分值。正式桌又默认启用两家归零、保米和海底，形成当前文档所述的组合规则。

| 项目 | 当前程序 | 荔枝帮助：进园子 | 荔枝帮助：敞开头 |
| --- | --- | --- | --- |
| 成牌 / 门清 | 20 / 20 | 10 / 10 | 20 / 20 |
| 混一色 / 对对胡 | 40 / 40 | 20 / 20 | 40 / 40 |
| 清一色 / 全球独钓 | 60 / 60 | 30 / 30 | 60 / 60 |
| 七对 | 80 | 30 | 80 |
| 一至三组四张的七对 | 160 / 240 / 320 | 80 / 120 / 160 | 160 / 240 / 320 |
| 压绝 | +40 | +20 | +60 |
| 大杠开花 | +40 | +20 | 总花数翻倍 |
| 无花果 | +40，且一律要求门清 | +20，帮助未写全资格 | +40，帮助未写全资格 |

因此，不能只把页面标题改成“进园子”，也不能用花砸 2 开关代替玩法模式：当前该开关只影响软硬花，不会缩放基础分、大胡和杠钱。

### P1：比下胡、接庄比和连续翻倍没有对局状态

计分函数虽有 `ctx.doubled`，但引擎 `winContext` 从不传入它，Game 也没有跨把翻倍状态。连庄、流局、花杠、大胡、包牌、罚分和一炮多响均不会因此改变下一把倍率。仅有计分分支不等于功能完成。

需要定稿：哪些事件影响本把或下一把、多个条件是否只翻一次、能否连续累计、何时清除、是否影响杠分。当前不应直接猜测这些组合。

### P1：天胡、地胡、天听限制和快照未接入

- **天胡**：从真实 `startRound` 构造合法起手成牌，再执行胡牌，实际只按普通成牌等项目结算，没有天胡（专项 G03）。
- **地胡 / 天听**：引擎没有天听标记、听口历史或“未换听”状态。`ctx.earthly` 同样没有调用来源；帮助中的天听后碰、杠、换听限制未实现。
- **快照**：同一家提供前三组碰牌后，再碰第四组，程序仍要求正常成对并出牌，不自动结束（G06）。清一色的第四碰快照也没有独立分支。

不同资料对天胡是固定分、独立结算还是三家归零有冲突；现在残留的天胡 +320 / 地胡 +280 参数不能当作已确定方案。

### P1：外包覆盖不完整

现在已实现：抢补杠胡包三家，大杠开花由原供牌者包三家，四组副露中至少三组来自同一家的承包。

未独立实现：进园子的全球独钓外包、清一色外包，以及快照对应结算。`settle` 先判断三口责任人，再判断抢杠或杠开；两种责任同时成立时，目前会优先由三口责任人支付。这是可读到的程序行为，但尚无已确认的对应规则牌例，需专门定稿，不能称所有包牌条件已覆盖。

### P1：压绝听牌提示漏牌（明确的前后端不一致）

固定牌例：自己已碰东风，手中为一三万、一二三筒、一二三条、南南，零硬花；桌面另一家已碰二万。

服务端收到最后一张二万时实际提供“胡”，按压绝算 **64 分**；自己的听牌提示却返回空列表（G01，同时验证了实际 `act → viewFor.actions`，不只调用算分函数）。

原因：`src/listening-hints.ts` 和 `winningKinds` 只带入自己手牌及自己的副露，没有把已经公开的对手碰牌传入 `visiblePungs`。结果把这手牌当成花数不足的小胡。修复时只需要使用公开碰牌，不应获取他人暗手或牌墙。

### P2：四连风、四人同牌罚分和部分特殊终局缺失

四连风开关及转账、四人依次打出相同牌的罚分没有接入事件流程，也没有判定中断、重置或下一把倍率的状态。现有 UI 标注了风罚分、接庄比待核对，但其余缺口没有全部展示。

哈灵另有花牌数量、幺九弃牌数量、三家同时胡的特殊终局模式；这些并不是可直接套用的通用规则，当前引擎没有实现。是否纳入应依据目标房型，而不是看到其他平台有就开启。[哈灵进园子说明](https://www.haling.com/news/news_42.html)

### P2：大胡叠加与轮庄有明确的平台差异

| 项目 | 当前可复现行为 | 影响与待定事项 |
| --- | --- | --- |
| 开门的大胡无花果 | 零硬花混一色只算混一色，不给无花果（G02，64 分） | 唐人游/来游戏描述的小胡门清条件没有一律限制大胡；当前文档有意更窄，须选定目标口径 |
| 全球独钓 + 独占 | 同时加 60 和 2（G05，牌例 128 分） | 来游戏明确不重复加独占；当前程序与之不同 |
| 一炮多响后坐庄 | 若原庄家不在赢家中就换下家（G04） | 来游戏的一炮多响保庄规则与当前不同 |
| 首庄 | 固定座位 0 | 没有随机首庄或掷骰定庄 |
| 暗杠 / 直杠与门清 | 暗杠保门清，直杠与补杠破门清 | 资料间条件不同；用户已明确暗杠不向他人显示，不能套用“亮一张”的他平台规则 |
| 杠的软花 | 数牌杠没有附加软花，风杠仅算一组风牌软花 | 部分平台按明/暗、风/数分别加软花；当前只另结即时杠分 |
| 单一听口 | 边、卡、独占统一先要求结构上只听一种牌 | 多听口是否仍可计独占，各平台不同；不能把压绝的单听要求一律外推 |
| 大胡后保庄 | 只看原庄家是否胡；大胡本身不保庄 | 目标玩法若大胡保庄，需要新状态与用例 |

这些是与具体参照的差异，不是无条件认定当前程序都算错。对照范围见 [唐人游](https://nanjingmj.uc55.com/Rule/Detail/201802_000241.html) 与 [来游戏](https://static.laiyouxi.com/games/44.html)。

### P2：发牌、海底、杠和保米边界需要写全

- **起手补花顺序**：当前逐家轮流拿单张，见花立即从尾部补完；没有先完整发牌再按庄家起顺序分轮补花。牌张守恒不证明实桌发牌顺序相同。
- **补花胡归类**：当前普通补花胡加 20，但不因此豁免开门小胡四硬花门槛；杠后补花再胡仍算杠开。目标规则若把补花胡作为大胡，需要单独调整资格。
- **海底开关**：当前同时控制留 16 张或摸尽，以及最后四张自摸加分。若目标房型只切换加分、不切换留牌，必须拆开。当前不是来游戏的“禁区点炮也加分”。
- **最后一张花**：关闭海底且 17 张墙时摸到花，花亮出后墙余 16，不能继续补，直接流局（E10）；杠的最低剩余牌数也沿用此门槛。
- **两家干与保米**：当前多人胡余额不足按比例分配；保米逐个处理赢家、选其他最高余额者补至 100。多人同时触发保米、已有另一位赢家成为出资人、出资人不足、责任冲突的目标规则未写全。用户已确认的单赢家牌例测试通过，不能用它证明所有多人边界均已定稿。

### P2：文案与规则版本记录不完整

1. `docs/RULES.md` 还说默认托管自动胡牌，实际 `trusteeAction` 遵照用户最新要求是只摸切、碰杠胡均过；还说默认全桌累计 90 秒，而当前新桌默认每次 10+90 秒，旧桌仍兼容累计模式。
2. 文案把弃胡写成下一次出牌前“不能再胡”；实际限制点炮/抢杠，自己下一次摸到成牌仍能自摸，应写清范围。
3. `RoundRecord` / `RoundReplay` 没有完整规则档案快照。完整 Game 保存规则，但导出的单把记录只含结果等字段，不能单靠它重算未来不同规则版本。
4. Rules 类型只支持一个规则 ID。后续实现新模式时须分版本，并保留旧桌的旧算分路径，不能直接改同名算法影响正在打的桌子。
