# 金陵麻将 · 网页管理后台与 APP 弹窗 V1

> 本文同时作为实现与验收说明。文案中的公告、Build 68 仍只是界面示例，不会作为真实公告或安装包自动发布。

## 入口与视觉

采用**独立网页管理后台**，管理员用电脑浏览器登录，集中处理公告、Android / iOS 版本与人员。左侧统一三个菜单「公告管理」「版本管理」「人员管理」，右上角显示管理员账号和「退出登录」。不增加统计仪表盘、独立权限配置、战队管理或财务页面。登录页只放账号、密码与「登录后台」。

网页和 APP 共用纸白、米白面板，墨绿正文与主按钮，哑金细线和小图标。网页使用侧栏和宽表格，右侧可放横屏手机预览；APP 保留当前横屏布局及「牌桌 / 约局 / 战绩 / 玩法 / 我的」五项底栏，在牌桌大厅页头增加带未读红点的公告铃铛入口。公告及更新弹窗采用居中纸色卡片、柔和蒙层，无音效。

公告只在**牌桌大厅**自动提示，正在麻将牌局内延后；普通成员只读。发布及人员管理入口统一放在网页后台，取消 APP「我的」中的内置发布表单。后台管理员权限由服务端校验，独立于 `guanli@1` 的开桌权限；本版展示角色身份和当前权限摘要，不提供权限配置界面。

## 公告管理

页面标题「公告管理」，说明「发布后，成员回到牌桌大厅即可查看」。右上角主按钮「新建公告」。列表按发布时间从新到旧排列，列为「标题 / 状态 / 发布时间 / 操作」，状态「草稿 / 已发布 / 已撤回」，操作「编辑 / 预览 / 撤回」。草稿没有撤回操作，已撤回项保留后台记录。

点击新建或编辑后，左侧填写、右侧展示横屏 APP 弹窗预览：

- **标题**：一句话说明，例如「欢迎来到金陵麻将」。
- **正文**：可分段，写清具体事情和时间；长文在弹窗内滚动。
- **预览**：展示牌桌大厅里的成员阅读效果，预览不推送。
- **保存草稿**：保留未发布内容，可稍后继续编辑。
- **发布公告**：标题、正文必填；成功提示「公告已发布，成员回到牌桌大厅后可查看」。

已发布公告可编辑后「发布新版」或「撤回公告」。编辑过程中保留线上原版，发布新版才替换内容并重新产生未读；撤回后不再弹出，不出现在成员公告列表。发布按钮提交时显示处理中，避免重复发布。

## 版本管理

页面标题「版本管理」，使用「Android / iOS」页签，每个平台分别展示当前线上版本和历史记录。列表列为「Build / 安装包 / 状态 / 发布时间 / 操作」；按钮「上传新版本」，状态「上传中 / 待校验 / 待发布 / 已发布 / 校验失败」。

上传区字段与操作：

- **平台**：继承当前 Android 或 iOS 页签。
- **安装包**：Android 上传 APK；iOS 上传**用户已签名并回传的 IPA**。上传后显示文件名、大小和进度，可重新选择。
- **Build**：读取安装包内置 Build 后展示，供管理员核对。示例为 Build 68。
- **更新说明**：填写用户能看懂的变化，例如「优化大厅体验，修复已知问题」。
- **校验结果**：显示包格式、应用标识、内置 Build、文件完整性等实际检测结果；错误写清原因。iOS 展示可读取的签名信息，安装适用条件未验证时明确标示，不把上传成功当成可安装保证。
- **预览更新弹窗**：展示当前平台成员看到的版本、说明与操作按钮。
- **发布更新**：安装包校验通过后可操作，点击后展示平台、Build、包名与文件哈希摘要，再「确认发布」。后台不设置无法证明的“已经实机安装”勾选项；iOS 的签名与设备适用限制继续明确提示。

上传区固定说明：「上传并校验后，点击发布更新才会对成员生效。」iOS 补充：「请上传你已完成签名的 IPA，后台不代替签名。」选文件、上传、校验或预览都不替换线上版本。确认发布后才更新对应平台的线上版本；两平台分别发布。成功提示「更新已发布，符合条件的成员将在下次检查时收到提示」。

版本编辑区域同样使用左侧表单、右侧横屏 APP 预览。预览区标记「APP 效果预览」，展示大厅背景和单个更新弹窗，便于发布前核对。管理表格中不混入下载收入、用户增长等无关指标。

## 人员管理

页面标题「人员管理」，说明「查看成员资料，维护所属战队与使用状态」。主区是宽表格，默认按注册时间倒序，最新注册成员排在最上；分页时保持此排序，不按昵称重新排列。

工具栏放搜索框「搜索账号、用户 ID 或昵称」，以及「全部战队」「全部状态」筛选与「重置筛选」。战队筛选含「未分配」；状态为「正常 / 暂停使用」。不放批量删除或删除账号主按钮。

表格列为「用户 ID / 账号 / 昵称 / 角色 / 所属战队 / 状态 / 注册时间 / 操作」。角色以轻量标签显示「成员」或「管理员」；所属战队显示最终生效的归属，未分配时明确显示「未分配」，不展示尚未保存的选择。注册时间显示到分钟，行操作以「编辑」为主，其他操作收在「更多」中。

点击「编辑」打开右侧抽屉，标题「编辑人员」，固定展示账号与用户 ID，包含：

- **昵称**：可编辑。
- **所属战队**：从现有战队选择，支持「未分配」；保存前展示原战队和目标战队。
- **角色身份**：只读显示「成员 / 管理员」，对应当前角色，不在本稿提供升降管理员操作。
- **当前权限**：独立显示「后台管理：有 / 无」「开桌权限：有 / 无」。仅真实账号 `guanli@1` 保留既定开桌资格，`role=admin` 不自动取得开桌权限；昵称改成 `guanli@1` 也不能获得开桌资格。
- **保存修改 / 取消**：保存后刷新列表中的最终昵称与战队；成功提示「人员资料已更新」。

「更多」菜单提供「重置密码」和「暂停使用」；暂停状态则显示「恢复使用」。使用以下简短确认流程：

- **重置密码**：确认框显示目标账号和用户 ID，提供遮挡显示的新密码与确认新密码输入框，说明「重置后原密码失效，该成员需重新登录」。按钮「取消 / 确认重置」。后台不展示或返回原密码，列表和操作记录不出现明文密码。
- **暂停使用**：确认框显示账号、当前状态和影响：「暂停后，该成员无法登录或进入新牌局；账号资料和历史记录保留。」可填写处理原因，按钮「取消 / 确认暂停」。如存在进行中牌局，确认框明确说明生效时机，不无提示地打断当前牌局。
- **恢复使用**：显示「恢复后，该成员可重新登录并使用应用」，按钮「取消 / 确认恢复」；恢复账号状态不改变角色、战队或开桌资格。

抽屉底部可展开「最近操作」，简洁展示操作人、时间、动作、变更前后值和原因。公告发布与撤回、版本发布、人员资料变更、密码重置、暂停和恢复均保留审计记录；密码只记录发生过重置，不记录内容。确认与保存成功前不改变线上状态，失败后保留输入并明确显示结果，避免管理员误以为操作已生效。

## 成员公告弹窗

结构为「小标签 公告 → 标题 → 发布时间 → 正文 → 我知道了」。短公告控制在一屏，底部确认按钮始终可见；关闭按钮或点「我知道了」均表示已确认该发布版本，点击蒙层不关闭。

**示例（设计文案）**

> 公告
> **欢迎来到金陵麻将**
> 2026年9月20日 18:00
> 牌友们好，欢迎来到金陵麻将。
> 开局前请先确认桌号和玩法，有问题可联系管理员。
> 后续活动与服务通知，会在这里发布。
> **我知道了**

进入大厅时，自动提示最新一条未确认公告；其余公告在入口后的列表按发布时间从新到旧查看。已确认版本不重复弹出，可从列表重看。仍有未读内容时保留入口红点。牌局中收到公告，等回到大厅再提示。

## OTA 更新弹窗

结构为「小标签 版本更新 → 发现新版本 → 目标 Build → 简短更新说明 → 主次按钮」。不强制更新；次按钮「稍后更新」，关闭行为与稍后相同。这里只表现真实已发布版本的数据，**Build 68 仅用于设计示例**。

**Android 示例（设计文案）**

> 版本更新
> **发现新版本**
> Build 68
> 优化大厅体验，修复已知问题。
> 下载完成后，按系统提示确认安装。
> **稍后更新**　**下载更新**

**iOS 示例（设计文案）**

> 版本更新
> **发现新版本**
> Build 68
> 优化大厅体验，修复已知问题。
> 前往安装页，按页面指引完成安装。
> **稍后更新**　**前往安装**

Android 点击后显示下载进度，完成后打开系统安装确认；失败显示「下载失败，请重试」，可重试或稍后。iOS 仅发布用户已完成签名、可安装的版本，主按钮前往对应安装页。

## 实现时的数据与时序

- 网页后台登录会话与所有写入接口均由服务端校验；隐藏按钮不能代替权限校验。APP 不提供公告发布和人员管理表单。
- 人员查询支持账号、用户 ID、昵称搜索，以及战队、状态筛选；排序使用真实注册时间倒序。人员修改必须以稳定用户 ID 定位，展示最终生效的所属战队。角色身份、后台管理资格和开桌资格分别计算，禁止用昵称或 `role=admin` 推导 `guanli@1` 的专属开桌资格。
- 密码重置、暂停使用和恢复均记录操作者与执行结果；账号历史与审计记录保留，不以删除账号代替暂停。密码变更后的会话失效、暂停对在途牌局的生效时机需要由服务端明确执行，并与确认框文案一致。
- 公告保存唯一 ID、发布版本、标题、正文、状态、发布时间及发布人；阅读记录按「成员 + 公告 ID + 发布版本」保存，切换设备仍可识别已读。浏览列表不自动清除所有未读，确认正文后才标记该版本已读。
- 公告管理接口校验管理员权限，普通成员接口仅返回已发布内容。发布或撤回后刷新大厅提示、列表与红点；接口失败不写入已读，也不反复打断用户。
- 版本记录按平台保存 Build、更新说明、包信息、校验状态、发布时间和发布人。安装包先进入待发布区，只有明确发布才切换线上版本指向；发布前重新核对平台、应用标识、Build、SHA-256，防止选错包或重复发布。同 Build 替换需要额外确认。Android 关联 APK 下载地址，iOS 关联已签名包与对应安装页。
- OTA 沿用当前原生端检查节奏：首次进入非牌局界面约 1.2 秒检查，回到前台且距上次检查至少 30 分钟时再查；仅服务端 Build 高于当前 Build 才提示。正在牌局时延后到大厅。
- 统一管理弹窗队列，同一时刻只显示一层；两项同时待提示时先 OTA、后公告。点击「稍后更新」或关闭更新提示后可看公告。若公告已展开才收到更新结果，等公告关闭再提示，避免内容突然被替换。
- 点击更新并跳转系统安装界面或 iOS 安装页时，公告保留待展示状态；返回大厅后继续。下载进度属于更新卡片本身，不叠加第二层弹窗。未读公告和可用更新状态分别存储，互不清除。
