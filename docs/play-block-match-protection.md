# 禁止参与对局：当前整桌保护

已于2026-09-26随0.8.2服务端部署，见 [部署记录](deployment-diagnostics-20260926.md)。

规则以第一把已经发牌为界，而非本家是否点过“准备”。

- 第一把尚未开始：被禁止参与的账号不能入新桌、准备或使当前等待桌开局；原客户端继续显示 admissionMessage。
- 第一把已开始：原席位可完成当前整桌（一般8把），包含 playing、claiming 和把间 ended；手动准备、自动续把、重连和服务重启均保留保护。
- 整桌 finished、已关闭、自动续开的新桌、其他席位都不受保护。禁玩标志不清除，新桌仍由 requirePlay 拒绝。
- 仍遵循原有提前终桌/破产等规则，不强行凑满8把。
- 仅豁免 playBlocked；不豁免账号暂停、密码重置、战队移除或强制更新检查。
- 使用服务端已保存的原席位、round 和 phase 判断，客户端不能声明保护资格；无需另建临时内存名单，因此重启不丢失。
- 原席位对局中的快捷短句、语音沿用同一保护判断；新邀请和新入桌仍严格检查权限。

客户端沿用现有错误提示条、结算界面和准备状态，不新增错误页面或协议，不需要重新打包 App。统一报错弹窗尚未在本次实现。

验证包含：禁玩后的第一把实际出牌、逐把续到第8把、结束后新桌拒绝、第一把前拦截、手动续把及真实服务重启恢复、账号暂停等安全边界。此文描述本地实现，不代表已经部署。
