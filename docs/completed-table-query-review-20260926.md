# 整桌统计查询复核

## 问题

1. 原 `completedTableWindow` 以积分行为外层，相关 `EXISTS` 逐行找终桌快照，不利于使用 `point_records_table_member` 缩小积分范围；最新记录的排序也被重复执行。
2. 周结直接关联周期内任意 `match_records`，只在周期内对 `game_id` 去重。遗留终桌快照跨周期时，同一桌会分别进入两个互不重叠的周期。

## 修正

- 使用非相关 `p.game_id IN (SELECT ...)` 构建本周期终桌集合。
- 先用 `match_records_time` 筛选日期；通过 `match_records_game_latest` 检查是否存在更新的终桌快照，不执行排序。时间相同时按唯一记录 ID 决胜。
- 判断更新快照时不限定日期范围，也不先排除练习快照，防止把已被范围外/不合格的新记录取代的旧记录算回来。
- 再通过 `point_records_table_member` 按桌查询原始积分流水。
- 后台积分统计及 CSV、Telegram 日结及周结共同使用此筛选。原计费、分母、战队归属、体验桌/解散把排除规则不变。
- 不新增索引或写入报表源库；报表工作进程可继续以只读方式读取已有生产索引。
