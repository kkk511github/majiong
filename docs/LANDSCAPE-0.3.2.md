# 0.3.2 横屏细节检查

2026-09-13。客户端 0.3.2，iOS build 8，Android 源码 versionCode 8。对局接口未变化，继续使用 SafeLink-212 上已验证的 0.3.1 后端。

## 本轮修复

- 个人页、战绩、玩法统一避开横屏刘海和圆角区域。
- 底部导航保留 Home 指示条所需空间，不再把按钮高度压缩到 44px 以下。
- 牌桌顶部菜单与托管扩大触摸范围，菜单图案保留原来的紧凑尺寸；顶部行高与实际按钮一致。
- 弹窗在左右安全边界之间居中，公开牌一览不伸入刘海区域。
- 窄横屏上，上方玩家移到安全区内的角落，避免昵称与右侧弃牌重叠。

- 四家的花牌直接显示，自己的在手牌左上方，其他三家随牌架排列。保留数量，补花后同步出现；不再需要展开“查看花牌”。大量补花时按各自区域紧凑排列，公开牌一览仍可放大查看。
- 为两侧花牌留出空间，避免花牌与弃牌混叠；932 宽度的安全区内，上方头像同样固定到角落。

- 修复连续点牌后的容器偏移：原牌桌会被浏览器滚动 18px / 10px，改为不可滚动的裁切区域，标题、花牌、头像与边框保持原位。三种横屏尺寸回归通过。

## 证据与范围

新增浏览器检查通过 Chrome 的安全区覆盖功能，设置真实 CSS `env(safe-area-inset-*)` 值：844×390、左右 59px；874×402 和 932×430、左右 62px；底部均 21px。检查导航/菜单/托管至少 44px、控件和手牌留在安全区、弃牌和昵称没有遮挡，并实际点击菜单扩大的边缘区域。

修复前检查复现：菜单仅 30×30px，托管 38×27px；导航/辅助页面的安全区处理不完整。修复后完整 44 项界面回归通过；随后头像位置修复通过 8 项相关回归，三种安全区尺寸再通过 4 项检查（其中新增 2 种尺寸）。这些是浏览器中的 CSS 与交互验证，不等同于 iOS 原生触摸和软键盘验收。

使用真实计时连续完成 4 局练习，237 秒内完成 1 次流局、3 次胡牌，自动操作、补花、结算、续局和四条战绩均正常。47 次采样中未出现手牌裁切或额外空隙，无页面异常；每局逐笔收支与四家净积分一致。详细记录见 `continuous-play-0.3.2.json`。这是约 4 分钟的连续玩法检查，不代表长时间运行、跨网络或微乐规则一致性证明。
