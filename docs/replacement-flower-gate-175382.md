# 175382 第八把：杠上开花误免硬花门槛

核查日期：2026-09-26。只读核对生产 `round_records` 与压缩回放，没有修改账目、积分或进行中的牌局。

## 事实

- 规则：`nj-garden-b-v3`，最低 4 朵硬花，本把倍率 2。
- 胡牌者已经碰过牌，不是门清；手中 2 朵硬花，无其他独立免花牌型。
- 回放顺序：暗杠八条 → 补到花牌 → 再补四万 → 自摸。
- 原账单为成牌 10、小杠开花 10、硬花 4、软花 4，再乘本把倍率 2，每份 56。
- 杠后再补花按现有规则记“小杠开花”，不是界面把大杠加分漏掉。
- 原胡牌流水实际收取 53、29、56，共 138 桌内分（前两家余额封顶）；另有正常暗杠收入 30。此处只列原始流水，不等同于可直接退款的修正方案。

## 根因与修复范围

`scoreNanjingBase` 调用 `big()` 时默认授予硬花豁免。大小杠开花都使用了此默认值，导致开门普通牌型只有 1–3 朵硬花也能胡。

当前 B 档修正为：大小杠开花保留原加分及比下胡资格，但本身不免硬花。门清、其他免花牌型及独立无花果规则不变，软花仍不能凑硬花门槛；旧规则版本行为不变。同步修正文案。

回归包含实际牌型、1–3 花拒绝、4 花放行、大小杠、门清/对对胡/无花果、旧规则、服务端不提供胡操作且拒绝直接提交。实际账单不自动重算：拒绝胡牌后原局应继续进行，不能假定后续结果，也不能简单删除胡分当成最终账单。

本次服务端修复尚未部署。后续客户端本地规则计算与文案已打入 [0.8.4 / Build81](release-0.8.4-build81.md)，但线上胡牌资格仍须部署服务端后才改变。生产核查时镜像为 `jinling-mahjong:0.8.3-whole-table-20260926`。
